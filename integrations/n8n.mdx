The [`n8n-nodes-manypi`](https://www.npmjs.com/package/n8n-nodes-manypi)
community node covers the ManyPI API, and its trigger starts workflows when
something happens in ManyPI. It also works as a tool for n8n's AI Agent.

## Install

In n8n, open **Settings → Community Nodes**, click **Install**, and enter:

```
n8n-nodes-manypi
```

## Connect your account

Pick **Authentication** on the node:

<Tabs>
  <Tab title="OAuth2">
    Create a **ManyPI OAuth2 API** credential, click **Connect my account**,
    and approve in ManyPI. There is nothing to copy. Needs n8n 1.119 or later.

    An OAuth2 connection can do anything your ManyPI account can. Published
    endpoints only accept API keys, so **Endpoint → Invoke** and **Get Result**
    need the API key option.
  </Tab>
  <Tab title="API key">
    Create a key under **API Access** in the ManyPI profile menu and add a
    **ManyPI API** credential with it. Give the key only the areas and actions
    the workflow uses. See [API keys and permissions](/platform/api-keys).
  </Tab>
</Tabs>

## ManyPI Trigger

The **ManyPI Trigger** checks ManyPI on n8n's polling schedule and starts the
workflow when:

| Event | Fires when |
| --- | --- |
| New Lead | A lead is saved, optionally filtered by status, search text or lead search |
| New Reply | A campaign gets a reply, auto-reply or bounce, optionally filtered by campaign and sentiment |
| Email Verification Reached Status | A verification job finishes |
| Agent Run Reached Status | An agent run reaches a status you pick. Add Paused to hear when it is waiting for an answer |
| Lead Search Reached Status | A lead search reaches a status you pick, Completed by default. Optionally one search only, by its run ID |
| Form Submitted | Someone submits a form you pick. Each answer is also under `fields`, keyed by the question |
| New Campaign | A campaign is created |
| Scraper Run Reached Status | A scraper run reaches a status, Completed by default |

When you activate the workflow, the trigger notes what already exists and
fires only for what appears or changes after that.

<Tip>
  For events the trigger does not cover, or to react within seconds, add a
  **Webhook** trigger node and point a [ManyPI webhook](/integrations/webhooks)
  at its production URL.
</Tip>

## Leads from one lead search

**Lead Search → Start** returns the search's `runId` and `status` at once.
A search takes a few minutes, so continue in one of two ways:

- Turn on **Wait for Completion**. The node holds the workflow until the
  search finishes, fails, or stops to ask a question, then returns `status`,
  `done`, `waitingForAnswer`, `leadsSaved` and `leadsWithEmail`. Searches
  still running after **Max Wait** come back with `waitTimedOut: true`.
- Or end the workflow there, and start a second one from the trigger's
  **Lead Search Reached Status** event.

Then add **Lead → Get Many** and set **Lead Search** to `{{ $json.runId }}`.
You get only the leads that search saved. **Lead Search → Get Status**
checks any search by its run ID.

**Number of Leads** sets how many leads a search finds, up to 250. Without
it, ManyPI finds 20.

## Example workflows

- **Weekly lead search**: Schedule Trigger → ManyPI **Lead Search → Start**
  with **Wait for Completion** on → **Lead → Get Many** with **Lead Search**
  set to `{{ $json.runId }}` → **Campaign → Enroll Leads**.
- **Form responses to your CRM**: ManyPI Trigger **Form Submitted** → your
  CRM node, mapping `email` and `fields.<question>`.
- **Positive replies to your CRM**: ManyPI Trigger **New Reply** with
  sentiment Positive → your CRM node.
- **Verify before import**: Google Sheets → ManyPI **Email Verification →
  Verify** → **Lead → Import**.
